# КПЦ Симбирск — генератор и база ориентировок

Статический PWA-проект с общей базой Firebase для подтвержденных пользователей.

## Что умеет
- Работает на телефоне и компьютере.
- Устанавливается на главный экран как приложение (если браузер поддерживает PWA).
- Автосохраняет текстовый черновик в браузере.
- Показывает живой предпросмотр.
- Создаёт PDF на устройстве без Apps Script.
- Сохраняет созданные ориентировки в общей базе Firestore.
- Разделяет активные поиски и архив по ПСС и ПТП.
- Поддерживает дневную и ночную темы с сохранением выбора на устройстве.
- Загружает несколько файлов треков в активный поиск и хранит их на Google Drive.
- После установки на Android принимает треки из системного меню «Поделиться» любого файлового менеджера.
- Поддерживает вход через Google и по email с подтверждением доступа администратором.
- Строит общую розу ветров за выбранные даты и часы по расчетной точке Open-Meteo или CSV метеостанции RP5.
- Подсказывает адреса во время ввода, показывает динамический полевой компас и формирует краткую текстовую сводку результата.
- Учитывает режим поиска ПСС или ПТП при ориентировочной оценке условий распространения запаха.
- Для ПТП сопоставляет ветер, порывы, влажность, температуру и осадки с профилем рельефа по предполагаемому шлейфу.

## Роза ветров

Длина сектора показывает, какую долю выбранного периода ветер приходил с этого направления. Цветные части сектора
показывают диапазоны скорости: менее 2, 2–4, 4–6, 6–8 и более 8 м/с. Штиль до 0,5 м/с не
учитывается. В результате отдельно показываются преобладающее направление, его средняя сила,
максимальный порыв и противоположное направление переноса запаха.

Режим ПСС предназначен для поиска живого человека на поверхности. Режим ПТП предназначен для поиска
погибшего и строже оценивает мороз и снег, которые могут ограничивать выход запаха. Направление ветра
и переноса запаха в обоих режимах остается одинаковым; меняется только вспомогательная оценка условий.
Эта оценка не заменяет проверку ветра у земли, рельефа и обстановки кинологом на месте.

Для ПТП дополнительно загружается профиль высот в точке поиска, на расстоянии 1, 3 и 6 км по направлению
переноса запаха, а также поперек него. Используется Copernicus DEM GLO-90 через Open-Meteo Elevation API.
Сводка описывает предполагаемую форму шлейфа, влажность, осадки, температуру и возможное влияние подъема,
спуска или неоднородного рельефа. Модель не видит лес, здания, малые овраги и фактический ветер у земли.

Поиск адреса использует Photon. Полевой компас разворачивает север, направление прихода ветра и
направление переноса запаха относительно верхней грани телефона. На мобильном устройстве браузер может
запросить разрешение на датчики движения и ориентации; без этого разрешения динамический компас недоступен.

Автоматический режим использует почасовые расчетные данные Open-Meteo. Режим RP5 читает фактический
CSV в кодировке UTF-8 со столбцами `DD` и `Ff`, а также `ff3`/`ff10` для порывов, если они есть.
Для режима RP5 на карте отображаются ближайшие реальные метеостанции из открытого каталога Meteostat.
Станцию можно выбрать по метке или в списке; при наличии WMO-номера в CSV она подбирается автоматически.
Соединительный пунктир показывается только после выбора станции и нужен для оценки ее расстояния до места поиска.
Каталог адаптирован из данных Meteostat и его поставщиков, распространяемых по лицензии CC BY 4.0.

## Карта треков поиска

- В активном и информационном поиске загруженные треки можно открыть вместе на полноэкранной карте.
- Каждый маршрут включается отдельной галочкой и показывается своим цветом; доступны выбор всех треков, снятие выбора и автоматическое приближение карты.
- Подложка переключается между обычной картой OpenStreetMap, рельефом OpenTopoMap и спутниковыми снимками Esri World Imagery.
- Поддерживается просмотр GPX, GPX.BIN, KML, KMZ, TCX и FIT. Файлы загружаются с Google Drive только после выбора и разбираются локально в браузере.

## Роли

- Владелец назначает и снимает администраторов.
- Администраторы создают, удаляют и архивируют ориентировки, управляют доступом пользователей и всеми заметками.
- Обычные пользователи просматривают общие ориентировки, создают PDF на устройстве и управляют только своими заметками.

## Архив на Google Drive

Архивирование создаёт PDF с ориентировкой, заметками и фотографиями и отправляет его в Google Apps
Script. Скрипт проверяет пользователя Firebase, загружает файл в папку
`10UIpRNpDoHZEb27ZD-AkhS0OQHgswBvN` и возвращает ссылку. Только после успешной загрузки тяжёлые данные
удаляются из Firestore, а в меню остаётся ссылка на архивный файл.

Треки `GPX`, `KML`, `KMZ`, `TCX` и `FIT` также загружаются через Apps Script в отдельные папки
активных поисков на Google Drive. В Firestore сохраняются только названия, авторы и ссылки на файлы.

Google Drive API и активация Google Cloud для сайта не требуются. Код загрузчика находится в
`google-apps-script/Code.gs`.

Для удаления ожидающих заявок из Firebase Authentication скрипту нужна служебная учетная запись:

1. В Firebase Console открыть «Настройки проекта» → «Сервисные аккаунты» → «Firebase Admin SDK».
2. Создать новый закрытый ключ и скачать JSON-файл. Ключ нельзя добавлять в репозиторий или передавать другим людям.
3. В настройках проекта Apps Script добавить свойство скрипта `FIREBASE_SERVICE_ACCOUNT_JSON` и
   вставить в его значение полное содержимое JSON-файла.
4. Создать новую версию развертывания веб-приложения, сохранив прежний URL.

## Публикация
Проект публикуется через GitHub Pages из ветки `main`, корень репозитория.

## Firebase

- Проект: `kpc-simbirsk`.
- Правила базы: `firestore.rules`.
- Первый администратор создается при первом входе владельца через Google.
- Публикация правил: `npx firebase-tools deploy --only firestore:rules,firestore:indexes`.

## Важное про офлайн

Черновик и ранее загруженные файлы интерфейса сохраняются локально. Авторизация, общие ориентировки,
изменение записей, карта и автоматическая загрузка погоды требуют подключения к интернету.
